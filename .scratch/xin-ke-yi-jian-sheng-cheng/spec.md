# Spec：新课一键生成草稿

Status: ready-for-agent

## Problem Statement

Haoyu 每天更新一课，每次都要手动做同一套机械步骤：复制最新一课的页面、逐处改 Day 编号、标题、og 信息、日期和面包屑，在 `assets/days.js` 最前面手写一条，再回到上一课把 pager 的「明天见」改成链接。步骤多、容易漏：漏改一处，新课页面上就会残留上一课的标题或链接；days.js 写错一个逗号，首页整个打不开。真正需要 Haoyu 动脑的只有三个版块（今天学了什么、我的练习、小工具），其余全是重复劳动。

## Solution

一条命令生成一份**草稿**：Haoyu 输入标题、一句话总结、图标字和小工具名，脚本自动算出 Day 编号、日期和第几周，以最新一课为底生成新页面，在 days.js 最前面加一条，并把上一课 pager 的「明天见」改成指向新课的链接。新页面里需要手写的三个版块只留写法示例和【待写】标记。脚本不做任何 git 操作；Haoyu 写完所有【待写】、`npm test` 变绿后自己推送，推送那一刻才算**更新**。

## User Stories

1. 作为 Haoyu，我想用一条命令生成新的一课，这样每天发课不用再手动复制粘贴。
2. 作为 Haoyu，我想只填标题、一句话总结、图标字和小工具名四项，这样生成一课只要几秒。
3. 作为 Haoyu，我想让 Day 编号自动取最新一课 +1，这样不会编错号。
4. 作为 Haoyu，我想让日期自动取今天、第几周按 Day 编号自动算，这样不用自己查日历和路线图。
5. 作为 Haoyu，我想在需要时用参数改 Day 编号或日期（比如补昨天的课），这样特殊情况也能用。
6. 作为 Haoyu，我想可以选填图标渐变和搜索关键词，这样想讲究时能讲究，不想时也能跳过。
7. 作为 Haoyu，我想让不填渐变的课自动用默认暖橙，这样图标不会是空的。
8. 作为 Haoyu，我想让新页面的 head（标题、描述、分享卡片信息）自动换成这一课的，这样链接发给朋友时卡片内容正确。
9. 作为 Haoyu，我想让新页面的 hero（图标、eyebrow「Day N · 当周主题」、大标题、一句话总结、日期和第几周）自动填好，这样我只需要微调大标题的换行。
10. 作为 Haoyu，我想让新页面的 pager 自动指向上一课，并在下一课位置显示「明天见」，这样翻页导航从第一天起就是对的。
11. 作为 Haoyu，我想让新页面页脚的面包屑自动变成「Day N · 标题」，这样不用再找这一处。
12. 作为 Haoyu，我想让三个手写版块保留正确的结构（id 是 learn / practice / tool，class 正确）并附一份写法示例，这样我照着写就不会弄坏版式和导航高亮。
13. 作为 Haoyu，我想让新页面里不残留上一课的正文和小工具脚本，这样忘了改的地方不会把 Day 7 的内容显示在 Day 8 上。
14. 作为 Haoyu，我想让需要我写的地方都标成【待写】，这样我搜一下就知道还剩哪些。
15. 作为 Haoyu，我想让 days.js 最前面自动多一条格式正确的记录，这样首页、搜索和「学完」分母都能认出新课。
16. 作为 Haoyu，我想让上一课 pager 的「明天见」自动变成指向新课的链接，这样读者能从上一课直接翻过来。
17. 作为 Haoyu，我想在新课页面已经存在时被拒绝，这样不会覆盖我写了一半的草稿。
18. 作为 Haoyu，我想在 days.js 里已经有这一课时被拒绝，这样不会出现重复的课。
19. 作为 Haoyu，我想在 Day 编号跳号或倒退时被拒绝，这样课号始终连续。
20. 作为 Haoyu，我想在 Day 超过四周计划（28 课）时被拒绝，并提示先在路线图里加一周，这样 eyebrow 的主题不会是空的。
21. 作为 Haoyu，我想在上一课找不到「明天见」时被拒绝，这样不会生成一份和上一课接不上的草稿。
22. 作为 Haoyu，我想在任何一条被拒绝时一个文件都不改，这样出错后不用手动收拾。
23. 作为 Haoyu，我想在必填项缺失时看到清楚的中文提示，告诉我缺了哪一项，这样不用去读代码。
24. 作为 Haoyu，我想生成后看到一份清单：新建了哪个文件、改了哪两个文件、还剩几处【待写】，这样我知道下一步做什么。
25. 作为 Haoyu，我想在没填搜索关键词时被提醒一句，这样我能决定要不要补上。
26. 作为 Haoyu，我想让脚本不提交、不推送，这样草稿不会在写完之前就被更新到网站上。
27. 作为 Haoyu，我想在草稿还没写完时 `npm test` 失败并指出是哪一课还有【待写】，这样我不会把草稿误当成更新推送上去。
28. 作为 Haoyu，我想在标题里含有 `<`、`&`、引号等字符时页面和 days.js 依然正确，这样标题想写什么就写什么。
29. 作为读者，我想每一课的分享卡片、导航、翻页和面包屑都和这一课一致，这样不会被上一课的残留信息搞混。
30. 作为读者，我想永远看不到写着【待写】的课，这样网站上每一课都是写完的。
31. 作为 Haoyu，我想在 README 里看到新的「每天新增一课」流程和一个完整的命令示例，这样隔一段时间再用也记得怎么做。

## Implementation Decisions

- **一个纯函数模块 + 一个很薄的命令行入口。** 模块对外只提供一个函数：输入最新一课的页面、上一课页面（即最新一课本身）、days.js 文本、字段和今天的日期，返回新页面、新的 days.js、改好的上一课页面（三段字符串），或者抛出一个带中文说明的错误。它不读写文件，因此 Node 可以直接测。命令行入口负责解析参数、读文件、调用模块、检查目标文件是否已存在、全部成功后才一次性写入三个文件，并打印清单。
- **零依赖，CommonJS**，写法和现有「学完记录」模块一致。`package.json` 加一个 `new-day` 脚本。
- **参数**：必填 `--title`、`--summary`、`--glyph`、`--tool`；选填 `--grad`、`--keywords`、`--day`、`--date`。`--day` 默认最新一课 +1，`--date` 默认今天（本地日期，YYYY-MM-DD）。
- **第几周**：`week = ceil(day / 7)`，当周主题取自 days.js 里的 `WEEKS`。超出 `WEEKS` 范围即拒绝。
- **读 days.js 的方式**：在 Node 的隔离环境里执行 days.js，取出 `DAYS` 和 `WEEKS`，用来找最新一课和当周主题，不用正则硬解析。新增那一条以文本形式插在 `window.DAYS = [` 之后，字段顺序和现有条目一致（day、keywords、date、week、title、summary、tool、glyph、grad、url），字符串用 JSON 转义；不填的 grad / keywords 不写这个字段。原文件其余部分一字不动。
- **新页面的生成方式**：以最新一课的页面为底，保留 head 里所有 meta（CSP、referrer、外观脚本、og、图标等）、导航、页脚结构和全站脚本引用，替换以下内容：
  - head：`<title>`、`description`、`og:title`、`og:description`、`og:url`
  - hero 整段：图标（有 grad 才写 `--g`）、eyebrow「Day N · 当周主题」、大标题 = 标题 +「。」、lead = 一句话总结、日期行「YYYY 年 M 月 D 日 · 第 N 周」
  - 三个版块（learn / practice / tool）整段换成内置的骨架：结构和 class 与 README 描述一致，每块附一份最小写法示例（一个 `feature`、一个 `result-card`、一个 `studio` 空壳），文字为【待写】
  - pager：上一课链接「‹ 上一课标题」+ 下一课「明天见」
  - 页脚面包屑：「Day N · 标题」
  - 删除上一课页面末尾的内联小工具脚本，只保留全站脚本引用
- **上一课的修改**：只把 pager 里「下一课 · Day N」的「明天见」占位替换成指向新课的链接「标题 ›」，写法与 Day 6 指向 Day 7 的链接一致。页面其余部分一字不动。
- **防呆（任一成立即拒绝，一个文件都不改）**：新课页面已存在；days.js 里已有这一课；Day ≠ 最新一课 +1；Day 超出 `WEEKS` 计划；上一课 pager 找不到「明天见」；必填项缺失或图标不是单个字。
- **转义**：写进 HTML 的字段做 HTML 转义，写进 days.js 的字段做 JSON 转义。
- **【待写】标记**是唯一的「还没写完」信号；脚本结尾统计新页面里【待写】的个数并打印。
- **README**：「每天新增一课」改为「先跑命令 → 写完三个版块的【待写】→ `npm test` 变绿 → 推送」，附完整命令示例，保留四个版块的写法说明；「测试」一节补一句 `npm test` 也检查草稿。
- 术语：`GLOSSARY.md` 新增「草稿」。

## Testing Decisions

- **好测试只测对外行为**：给定输入，看生成的三段字符串里有没有该有的东西、有没有不该残留的东西，以及什么情况下拒绝。不测内部用了哪些替换步骤。
- **主 seam：草稿生成模块的那一个函数。** 用仓库里真实的最新一课页面和真实的 days.js 当输入（测试读取文件后把字符串交给函数），覆盖：
  - 新页面的 head、hero、pager、面包屑都是新课的信息，并且不再包含上一课的标题和小工具脚本
  - 三个版块的 id 是 learn / practice / tool，含有【待写】
  - 不填 grad 时图标没有 `--g`，填了就有
  - 第几周和当周主题算对（例如 Day 8 → 第 2 周「Claude Code 与图片」）
  - 新的 days.js 能被执行，`DAYS[0]` 就是新课且字段正确，原有各课不变；不填 grad / keywords 时没有这些字段
  - 上一课的「明天见」变成指向新课的链接，其余部分不变
  - 标题含特殊字符时 HTML 和 days.js 都正确
  - 每一条防呆规则都会拒绝，并给出中文说明
- **次 seam：命令行冒烟测试**（一两个）。在临时文件夹里放一份仓库副本跑命令：正常情况下三个文件被写入；触发防呆时（例如目标页面已存在）三个文件都不变，退出码非零。
- **仓库内容检查**：一条测试读取 days.js 列出的每一课页面，断言其中没有【待写】。有草稿时它失败，这是有意的。
- 用 Node 自带的 `node --test`，不装依赖。参照现有的 `test/xuewan.test.js`：中文测试名、使用 GLOSSARY 里的术语（课、更新、草稿）、只通过对外接口检查。
- 新页面在浏览器里的样子不写自动化测试，生成后由 Haoyu 打开草稿看一眼即可。

## Out of Scope

- 自动写三个版块的内容（笔记、练习、小工具），或调用任何 AI / 网络服务
- 任何 git 操作（提交、推送、开分支）
- `--dry-run` 预览模式
- 修改路线图 `WEEKS`、首页或全站脚本
- 改已经更新的课（重命名、删课、改号）
- 选择不同的写法模板（Day 1「三次尝试对比」/ Day 2「采访对话」），骨架只有一种
- 自动生成图标渐变或搜索关键词
