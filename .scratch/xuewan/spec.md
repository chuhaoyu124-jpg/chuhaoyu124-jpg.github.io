# Spec：读者给课标记「学完」

Status: ready-for-agent

## Problem Statement

读者跟着网站一课一课学，但网站记不住他学到了哪里。首页上的「进度」其实是 Haoyu 已经**更新**了几课，跟读者自己学完了几课没有关系。读者隔几天回来，只能靠记忆判断哪几课已经看过、下一课该从哪里开始。

## Solution

每一课的页面底部有一个按钮，读者读完后点一下，就把这一课标记为**学完**；再点一次可以取消。记录只保存在读者自己的浏览器里。首页顶部多一个数字「已学完 N / M」（M = 已更新的课数），学完的课在首页课程卡上显示 ✓。原来首页上表示更新进度的文字改用「更新」一词，避免和「学完」混淆。

## User Stories

1. 作为读者，我想在一课的页面底部点「标记为学完」，这样我能记下自己已经读完这一课。
2. 作为读者，我想在点完之后看到按钮变成「✓ 已学完」，这样我能确认标记成功了。
3. 作为读者，我想在点完之后看到一句「学完 Day N 🎉」的小提示，这样我会有一点完成的成就感。
4. 作为读者，我想在点错时再点一次「✓ 已学完」就能取消，这样误点不会留下错误记录。
5. 作为读者，我想在取消时看到「已取消学完」的小提示，这样我知道取消生效了。
6. 作为读者，我想把鼠标移到（或在手机上长按）「✓ 已学完」时看到「再点一次取消」的提示，这样我知道可以撤销。
7. 作为读者，我想在按钮旁看到一行「记录只保存在这个浏览器里」，这样我换设备时不会以为记录丢了。
8. 作为读者，我想在刷新页面或几天后再来时，学完的标记还在，这样我不用重新标记。
9. 作为读者，我想在首页顶部看到「已学完 N / M」，这样我一眼知道自己跟上了多少。
10. 作为还没学完任何一课的读者，我想在首页看到「已学完 0 / M」，这样我知道这里可以记录进度。
11. 作为读者，我想在首页课程卡上看到学完的课带 ✓，这样我能快速找到下一课该看哪一课。
12. 作为读者，我想在首页课程卡上不会误点到「学完」，这样我只在真正读完一课时才标记。
13. 作为读者，我想在 Haoyu 新更新一课后看到分母随之变大（比如 3 / 7 变成 3 / 8），这样「学完」始终反映我是否跟上了已更新的内容。
14. 作为读者，我想在首页看到「已更新」而不是「四周课程进度」、在路线图看到「已更新 N / M 天」而不是「已完成」，这样我不会把 Haoyu 的更新和我的学完搞混。
15. 作为用无痕模式或禁用了网站数据的读者，我想网站照常能看、按钮点了也不报错，这样功能失效时不影响阅读。
16. 作为在手机上看的读者，我想这个按钮和首页数字在手机、iPad、电脑上都正常显示，并跟随浅色 / 深色外观，这样体验和网站其它部分一致。
17. 作为 Haoyu，我想新增一课时不需要为「学完」多做任何事，这样每天发课的流程不变。

## Implementation Decisions

- **新建一个「学完记录」小模块**，只负责记录哪几课学完了，不碰页面。它对外提供：查询某一课是否学完、切换某一课的学完状态（返回切换后的状态）、给定已更新的课列表时算出「学完数 / 已更新数」。
- **存储可以替换**：模块接收一个存储对象（只需 get / set 两个方法），浏览器里传入现有的 localStorage 安全包装，测试里传入内存假存储。这样模块不依赖浏览器，Node 可以直接加载。
- **同一份文件在浏览器和 Node 都能用**：浏览器里以普通 `<script>` 引入、挂到 `window` 上；在 Node 里通过 `module.exports` 导出。不引入打包工具，不违反页面的 CSP（同源脚本）。
- **按 Day 编号记录**：localStorage 里用一个固定键存学完的 Day 编号列表（JSON 数组）。
- **容错**：存储不可用（读写抛错）时，当作什么都没学完，切换操作不抛错；存的值损坏或不是数组时，当作空列表。
- **分子只算已更新的课**：如果记录里有某个 Day 不在已更新列表中（例如这一课后来被撤下或改号），它不计入「学完数」，分子不会超过分母。
- **课程页**：在每课底部、上一课 / 下一课之上自动插入按钮和说明小字，由现有的全站脚本统一生成，新课页面不需要手写。按钮文字：未学完「标记为学完」，学完「✓ 已学完」，悬停 / 长按提示「再点一次取消」。点击后用现有的小提示组件弹出「学完 Day N 🎉」或「已取消学完」。
- **首页**：顶部数字从三个变成四个，新增「已学完 N / M」；课程卡上学完的课显示 ✓，卡片本身点击行为不变。
- **改名**：首页「四周课程进度」改为「已更新」；路线图「已完成 N / M 天」改为「已更新 N / M 天」。术语见 `GLOSSARY.md` 中的「更新」「学完」。
- **README** 更新：在功能说明里加上「学完」一节，并写明测试怎么跑。

## Testing Decisions

- **只有一个测试层（seam）：「学完记录」模块。** 测它的对外行为（是否学完、切换、计数），不测内部怎么存。
- 用 Node 自带的测试工具（`node --test`），不装任何第三方依赖；仓库里加一个最小的 `package.json`，`npm test` 即可运行。
- 要覆盖的行为：
  - 初始时任何一课都没学完，计数为 0 / M
  - 切换一次变为学完，再切换一次取消
  - 记录在「重新加载」后仍然存在（同一个假存储新建一个模块实例）
  - 多课分别标记，互不影响
  - 计数只算已更新的课；不在列表里的 Day 不计入
  - 存储读写抛错时不抛出、视为未学完
  - 存储里是损坏的值时视为空
- **页面部分不写自动化测试**：按钮、首页数字、✓ 和改名的文字在完成后用浏览器手动走一遍（课程页标记 → 首页检查 → 取消 → 刷新 → 手机尺寸 → 深色外观）。
- 仓库里目前没有任何测试，这是第一个，没有可参照的已有测试。

## Out of Scope

- 搜索面板（⌘K）里显示 ✓
- 路线图里显示每周学完数
- 跨设备同步、账号、导出 / 导入记录
- 在首页课程卡上直接标记学完
- 滚动到底自动标记
- 「一键清空全部学完」

## Further Notes

- 网站发布在 GitHub Pages，`.scratch/` 和 `package.json` 也会被公开发布，这是已确认可以接受的。
- 页面 CSP 禁止网络请求，所以记录只能存在浏览器本地，这也是「记录只保存在这个浏览器里」提示的原因。
